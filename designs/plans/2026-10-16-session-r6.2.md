## Lifecycle and security invariants

- One native session client owns hello/welcome and registry state per verified,
  authenticated host connection. Connections and terminal windows share that
  client; opening a window never sends another hello on a welcomed attachment.
- A replacement authenticated connection clears registry values, sequence,
  tombstones, pending replies, terminal streams and leases. Keep only durable
  host trust/runtime fences and command recovery metadata. A new attachment's
  first snapshot may start at any sequence. Never infer identity from the relay.
- Removed agent-list, terminal-list/control and unbound chat/voice mutation
  paths have no fallback. Browser access remains disabled pending section 9.
  Native terminal requests use exact session/process/attachment bindings.
- Session errors may omit correlation for removed/undecodable requests. Valid
  terminal errors retain terminal id, optional stream id, code and message;
  chat errors retain code. A stale stream error cannot close its successor.
- Host admission is permission, accepting session, then lease. Client controls
  require permission and a running session; refusals invalidate stale control
  or refresh state, without replaying a prompt, input or stop. A busy response
  keeps the durable request identity available for receipt recovery.
- Preserve monotonic expiry and late-reply fencing. Epochs may skip. Read-only
  viewers and snapshots never grant control; reconnect never reacquires it.
- Import all r6.2 fixtures byte-for-byte, pin their provenance and hashes, run
  every client scenario through real Swift/JavaScript decoders, and exercise
  host-family messages as wire inputs. Host execution remains the Atem owner's
  responsibility; do not claim client tests execute a Rust host.
- r7 approval decisions remain out of scope until the contract is supplied.
