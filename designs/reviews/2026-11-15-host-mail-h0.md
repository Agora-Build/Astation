# Atem host-mail H-0 contract review

Reviewed Atem PR #168 at `527a7c89e647bdaecc16bde5b2ac9f02578108d6`,
including host-work-v1 section 11.5, the delegated design changes, the
session-v1 pointers, and proposed VII.B tests 37a-37l.

## Result

No Critical or High contract finding. Astation agrees to D1, D3, D4 and
proposals a-e on this source. This is agreement on the design, not evidence
that either implementation, a joint check, or a rollout is complete.

- Atem hosts use their existing host identity and sealed host-mail objects.
  Station integrations remain available for other callers. Project grants
  remain signed, and the first version needs no vault directory.
- Accept eight live puts and eight live dones per link generation, one live
  sync, one object per page, 512 KiB mailbox messages, and 256 KiB heads.
  Enforce size limits before parsing and persist objects before receipts.
- Accept caller-owned put identifiers in refusals. Sync/done refusals remain
  metadata-free. Account, genesis, host, trust generation and socket authority
  must be checked again at the actual response write, as for Part I.
- Accept canonical identity hashing over the decoded signature/seal bytes,
  per-recipient idempotency, and charging a delivery again after removal.
  Receiver-side durable verdicts remain the protection against executing a
  duplicate. Station storage is never execution acceptance.
- Accept marking an undecided pending overflow done without claiming its ID
  or inventing a verdict. Accepted pending objects stay undoned. Commit owed
  dones and cursor with the receiver's durable decision before sending them.
- Accept fixed no_match/resolved forms only in sealed status objects and
  deterministic result IDs checked against the task everywhere. Independently
  recalculated the three UUID examples in the draft; they match.
- Accept select only in host envelopes, explicit launch: true only with an
  eligible named route, route consent and project launch authority, and one
  aggregate budget of 32 local and remote agents. Project labels address;
  project principals consent. Consent alone must not create a label match.
- Accept the host encryption key in the normal verification reveal, bound by
  its host-channel signature to account/genesis/host/generation. Show both
  exact entry bodies under one fresh confirmation. A changed body requires
  another confirmation. While the verifier gate is closed, append only
  add_host. A partial commit must preserve the exact signed key-entry retry,
  or finish without a key and require a later fresh manager confirmation.

## Implementation and evidence still required

The shared library must provide the strict mailbox readers/builders, feature
handling and conformance vectors before Station adopts the new wire. Exercise
account/trust/socket replacement behind queued replies, wrong-mailbox done,
lost commit replies, concurrent duplicate puts, overflow/resend, reset,
durable-key-before-reveal, both gate states, and each pairing partial-commit
path in the proposed joint tests. Unknown or incomplete verifier inventory
keeps new signing disabled.

Part I remains Astation #79 / draft #82, followed by VII.A. Host-mail
implementation follows this agreement; VII.B follows VII.A. This review does
not merge, deploy, or enable delegated execution, host senders or new signing.
