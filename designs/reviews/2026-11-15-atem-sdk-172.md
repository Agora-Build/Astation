# Atem PR 172 shared-library review

Reviewed `4283ec9cbe2a98911a934eb525706fd49064e624`, against base
`5ee2bbe30710e883c3f49c74e1bf1a7c67e100e3`, for Astation's two SDK points
and H-0 proposals c/d. Source was downloaded into an isolated review tree;
the running host, app, installed packages and Astation SDK pin were unchanged.

## Decision

No blocking finding. Astation signs off this source for the result ID check
and refusing channel selectors.

- The runtime re-exports the shared UUID v5 result ID derivation. Its namespace
  and exact input are unchanged, including selector task UUIDs, so existing
  stored result IDs remain valid.
- A non-null reply answers only the requested task's deterministic result ID.
  Null replies still answer their own query. Existing request, host, channel
  and attachment checks remain in force. Dropped and publishing replies do not
  bypass the new check.
- `Attached::on_frame` checks correlation before removing the outstanding
  request or emitting a family event. The binding closes its channel on that
  malformed result. Recovery queries need a fresh connection/request ID; this
  change does not authorize replaying a mutation.
- `Message::valid` refuses a channel message with any select recipient before
  sealing or host admission, including a mixture of select and ordinary
  recipients. Local and host-sender validation retain select. Reading an old
  stored message receipt does not revalidate its message as a new publication;
  the documented distinction between retry and query remains valid.
- UniFFI and WASM expose the same derivation. UUID generation here is purely
  deterministic and introduces no random or platform-specific dependency.

## Validation

All applicable CI jobs pass on the reviewed head: Linux, Intel/Apple Silicon
Macs, core Windows, Rust/Kotlin/WASM, Swift conformance and Apple packaging,
Android libraries, and the r9 harness. Automated review jobs are skipped, not
additional review evidence.

Local core/binding run: 645 unmodified-source tests pass, 11 remain ignored,
with one pre-existing host-policy test excluded after reproducing its failure
on both the PR and its exact base. Two extra temporary binding probes also pass
(647 total in the combined run). They use a real authenticated channel and
`ClientConnection::send_json`/`on_frame`:

- A correct or null reply produces an event and frees its request. A reply for
  another task produces `malformed`, no event, and a closed connection.
- Both select-only and mixed-recipient channel messages are refused before
  sealing, while the connection remains attached.

The independent Python checker passes all 484 cases. The temporary probes
modify test scaffolding only in the isolated review tree; they are not claimed
as committed upstream coverage. Retaining equivalent connection-level
regressions upstream is recommended, as already listed in the PR follow-ups.

## Separate baseline test issue

`crates/atem-client/tests/client_e2e.rs:1561` expects host_policy_changed in an
exchange that stops as soon as the policy result arrives. The host may deliver
the direct result before its queued change notification. This fails locally
at the same line on the PR and unchanged base, including an isolated retry.
The test should wait for both events or collect the change separately. This
is not a result-ID/select regression and does not block this sign-off. The
unfiltered local suite is therefore not reported as fully passing.

## Boundaries

Sending-host result_id_mismatch checks belong to the host-mail implementation
and remain separate. This review does not claim host mail, delegated joint
tests, SDK adoption, deployment or feature activation. Part I issue 79 remains
the critical path; no signing or execution gate changes here.
